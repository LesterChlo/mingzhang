## 四、AI 对话实现方式

- **引擎**：`Engine` 类（`src/main/engine/engine.ts`，43.9KB）装配 pi 引擎
  - `ModelRuntime` + `SessionManager` + 自定义工具 `createLedgerTools`
  - 密钥 `InMemoryCredentialStore` + `setRuntimeApiKey` 运行时注入，**不落 pi 任何文件**
  - `noTools:'builtin'` 关闭全部内置工具，工具面 = 账务工具
- **系统提示**：`MINGZHANG_SYSTEM_PROMPT`（`system-prompt.ts`）——「记账中心，对话式记账助手」，强制调 `record`/`query` 工具，金额整数分，不确定就问
- **工具**：`tools.ts`(23KB) + `tools-m2~m5`（多版本迭代），含 record/query/read_bill/apply_bill/commit_batch 等
- **事件流**：pi 事件 → `onPiEvent` → IPC 广播 `mz:chat-event`（text-delta/tool-start/tool-end/agent-end 等）
- **超时保护**：空闲 60s + 总预算 10min 双层看门狗
- **Ollama 调用**：OpenAI 兼容 `http://127.0.0.1:11434/v1`，model=`qwen3-4b-32k`（固化 num_ctx=32768）

**结论**：AI 对话模块成熟，**必须完整保留**，新经营模块作为独立 Tab 并存。

## 五、启动方式与黑窗口成因（重点）

### 当前启动链
```
桌面快捷方式
  → <便携运行目录>\一键启动.bat（CMD 窗口 = 黑窗口②）
      → start "Ollama本地模型" /min cmd /c "<本地模型目录>\start.bat"（最小化 CMD = 黑窗口①）
      → start "" "<便携运行目录>\jizhangzhongxin.exe"
      → timeout /t 8 → exit
```

### 两个黑窗口的来源
| 窗口 | 来源 | 可见性 |
|---|---|---|
| 黑窗口① | `start "Ollama本地模型" /min cmd /c "<本地模型目录>\start.bat"` 启动的最小化 CMD | `/min` 最小化到任务栏，**仍可见**，且是 Ollama 的父进程 |
| 黑窗口② | `一键启动.bat` 自身的 CMD | 运行 echo/curl/timeout 期间可见，8 秒后 exit 关闭 |

### 关闭窗口导致退出的原因
1. **Ollama 被 cmd /c 包裹**：`start ... /min cmd /c "start.bat"` 让 Ollama 成为该 cmd 的子进程。**关闭这个 cmd 窗口 → Ollama 进程被终止**。
2. **主程序与启动器无解耦**：`jizhangzhongxin.exe` 虽用 `start ""` 独立启动，但 Electron 主进程 `index.ts` 的 `app.on('window-all-closed', () => app.quit())` —— 关闭主窗口直接退出整个 app，**没有托盘、没有最小化到后台**。
3. **进程父子关系**：启动器 bat 是 Ollama cmd 的祖父，关闭 bat 不直接影响已 start 出去的进程，但用户分不清哪个窗口能关。

### 解决方向（第二阶段）
- **Ollama 无窗口启动**：用 Electron 主进程 `child_process.spawn(detached:true, stdio:'ignore', windowsHide:true)` 或独立 VBS/PowerShell `-WindowStyle Hidden` 启动，脱离 cmd 父进程
- **进程解耦**：Ollama 作为 detached 独立进程，主程序退出不杀它；启动前 `curl /api/version` 检测已运行则跳过
- **系统托盘**：Electron `Tray` + `Menu`，关闭按钮 → 最小化到托盘（可选），`window-all-closed` 不再直接 quit
- **无启动器 bat**：改造为 `jizhangzhongxin.exe` 直接启动，内部管理 Ollama；桌面 lnk 指向 exe 本身（自带图标）

## 八、风险与约束

1. **数据安全**：现有 `mingzhang.db` 156KB（含测试数据），升级前必须备份；schema 扩展用增量迁移，不重建原表。
2. **密钥绑定**：Electron safeStorage 密文绑定应用身份 + userData，改 `app.setName` 或数据目录会导致密钥失效。
3. **构建工具残留**：Visual Studio Build Tools 目录体积大且普通权限删不掉，但不影响构建（原生模块用 prebuild）。
4. **Ollama 进程管理**：detached 启动后，主程序需可靠检测存活（`curl /api/version`），避免重复启动。
5. **范围控制**：15 阶段需求庞大，建议按优先级分批交付，每阶段测试通过再继续。
