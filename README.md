# 明账 · MingZhang

本地优先的 AI 记账桌面应用，面向 Windows。适合隔一段时间集中导入账单，再把分类和疑点整理清楚；也可以用一句话或一张截图记一笔。

账本保存在本机。**启用云端模型后，你交给它的文本、图片，以及工具返回的账单内容或查询结果，会发送给所选模型供应商。** 本地存储不等于所有处理都离线，详见[数据与隐私](#数据与隐私)。

## 导入之后，把账整理清楚

导入完成不代表每笔账都已经确认。明账把剩下的事留在界面上：哪些已处理、哪些疑似重复、哪些缺信息、哪些不计收支，都能继续查看。

1. **导入并确认批次。** 拖入 CSV / XLSX，检查读表方案。缺方向、日期或账户等必要信息的原行会留作待办，补齐后继续处理，不另造一笔代替原行。
2. **按商户复核分类。** 有依据的建议先填好，拿不准的留白。可以展开逐笔明细、排除个别记录，也可以只确认选中的一部分。
3. **查看结果，必要时撤销。** 分类确认只处理所选记录，不重复记账。离开页面或重启后，可以继续查看本批结果及尚未完成的部分。
4. **决定要不要记住。** 确认分类不会自动保存长期习惯。“下次也这样分”需要另外选择、保存；不保存也能正常记账。

## 还能做什么

- **单笔速记与截图记账：** 解析结果先待确认，补齐必要信息后由你入账；高置信度和分类习惯命中都不代替这次确认。
- **账本筛选与纠错：** 按月份、类型、分类、账户、金额、状态或关键词查找，编辑金额、日期、收支类型、分类和账户。
- **拆账与不计收支：** 拆账分项必须与原金额核对一致，先预览方案，再由界面确认；保留原笔和来源，可撤销整组拆账。不计收支保留记录，也可以恢复计入。
- **交易附件：** 在本机查看、添加、移除和预览同一笔交易的多张图片；这类附件管理不会自动把图片重新发给模型。
- **账户与分类管理：** 新建、改名，查看各账户已确认的月度收支，跳转到对应流水。这里展示的是已记流水，不是银行卡余额。
- **报告与预算：** 按月看收支、分类分布和历史月份，点分类继续查账；预算是支出计划，不是账户余额。
- **助手与历史：** 问账、查看工具执行结果、生成批量分类或拆账方案；保留当前会话历史，支持重新读取与恢复。
- **快照和恢复：** 本地快照、口令备份包、恢复检查与异常启动出口。重要数据仍应另做备份，不把程序校验当作永不出错的保证。

## 模型负责判断，程序负责搬运

导入 CSV / XLSX 时，模型判断列的含义、排除条件和分类建议；程序从原表读取金额与日期、去重、核对笔数并落库。原表金额不靠模型逐行复述。

批次方案必须满足：

```text
材料行数 = 将入账 + 重复跳过 + 待核对 + 不计收支
```

截图没有原表单元格可供程序复读，金额仍依赖视觉模型识别，所以需要在确认前核对。程序约束能防止一部分搬运和执行错误，不能保证模型理解正确。

Agent 只接入 16 个账务工具，没有 shell、任意文件读写或网页访问工具。模型发起的删除、批量入账、拆账等动作要经过对应的界面确认；模型自己说“用户已确认”不算授权。

分类习惯在 **设置 → 分类习惯** 中管理，只影响后续建议，不追改历史账目。

## 从源码运行

需要 Windows 和 **Node.js ≥ 22.12**，推荐使用 Node.js 24 LTS。

```bash
git clone https://github.com/LesterChlo/mingzhang.git
cd mingzhang
npm ci
npm run dev
```

首次启动可以先选离线演示，不需要 API Key。它是本机 loopback 服务提供的**确定性假模型**，只覆盖预置规则和样例，不是本地大模型，也不能代表真实模型的理解能力。

处理自己的文本或截图前，可在 **设置 → 模型服务** 添加预设、填写模型服务并测试连接。支持多个预设及自定义端点；截图解析需要支持视觉并通过相应自检的模型，当前没有本地 OCR 兜底。

## 技术实现

| 层 | 实现 |
| --- | --- |
| 桌面与构建 | Electron 44、electron-vite |
| 界面 | React 18、TypeScript |
| Agent | 以 SDK 嵌入 pi，工具范围限于账务 |
| 账本 | SQLite，`better-sqlite3-multiple-ciphers` 加密 |
| 系统密钥保护 | Electron `safeStorage`，Windows 使用 DPAPI |
| 表格与测试 | SheetJS、Vitest、Playwright |

```text
src/main/       账务领域、Agent、存储与 IPC
src/preload/    受限的界面调用接口
src/renderer/   收件箱、账本、报告、账户、设置及助手
src/shared/     跨层类型
tests/          领域测试、集成测试与真实窗口巡检
```

## 数据与隐私

- 账本文件默认位于 `%APPDATA%\mingzhang\mingzhang.db`。打包程序旁存在可写的 `data/` 时可使用便携数据目录；开发和测试可用 `MZ_DATA_DIR` 指定独立目录。
- **加密范围要分清。** SQLite 账本加密；会话历史和附件原图是另外的本地文件，不要把“账本加密”理解成整个数据目录都加密。
- 模型 API Key 使用系统安全存储保护。数据库快照和口令备份不是完整应用目录迁移，换机需重新配置模型服务。
- **附件原图要另备份。** 数据库快照和口令备份包含交易的附件引用，不包含原图；换机时另行保存 `attachments/` 目录，不能只带走数据库。
- 应用没有内置账号或云同步。云模型可收到你提交的文本、图片，以及它通过工具请求读取的账单表头、行内容或查询结果；供应商的留存政策由其决定。
- 不想把材料发送给云端服务时，不要启用云模型；内置离线演示只连接本机服务。不要用真实账本截图制作公开演示。

## 当前边界

- 当前版本为 `0.1.0`，构建目标是 Windows x64，尚无 macOS / Linux 桌面交付。
- 构建产物未做代码签名，Windows 可能显示未知发布者或 SmartScreen 警告；这不要求你关闭安全软件。
- 不连接银行、微信或支付宝做后台自动扣账；需要你提供账单文件、文本或截图。账户流水不能替代平台真实余额。
- 图片识别效果取决于所选视觉模型。离线演示是规则脚本，不能处理任意材料，也不能作为真实 AI 效果展示。
- 这是仍在迭代的个人记账应用，不是专业会计系统。恢复、迁移或批量调整前，先留一份可用备份。
